Power Apps Hands-On Lab

Build a simple Network Capacity Monitoring app using Dataverse and a model-driven app. The goal is to experience the core build features, not finish a production solution.

Beginner-friendly60 minutesModel-driven appDataverse
Goal1. Create data2. Build app3. Customize4. DashboardBonus

What you will build

By the end of the lab, you will have a small model-driven app where an operations user can view network capacity requests, open a request, update its status, filter the records, and view a simple chart.

Lab outcome
  • 1 Dataverse table
  • 1 model-driven app
  • 3 useful views
  • 1 customized main form
  • 1 chart
Suggested timing
  • 5 min: Setup
  • 15 min: Create table
  • 15 min: Build app
  • 15 min: Customize views and form
  • 10 min: Chart, test, wrap-up

Before you start 5 min

  1. Go to make.powerapps.com.
  2. Select the environment provided by the facilitator.
  3. Confirm that you can create Dataverse tables and apps.
  4. Keep this guide open in another browser tab.
Keep it simple: this participant lab intentionally uses one table. Approval automation and additional related tables are facilitator demo extensions.

Lab 1: Create the Dataverse table 15 min

Step 1: Use Copilot to create the table

From Power Apps, create a table using Copilot or the natural-language table creation experience. Paste this prompt:

Create a Dataverse table called Network Capacity Request for monitoring telecom capacity upgrade requests. Include these columns: - Request Title: text - Site ID: text - Region: choice with Jakarta, Surabaya, Bandung, Medan, Makassar - Peak Utilization: decimal number - Requested Upgrade: choice with Add 5G Capacity Layer, Carrier Expansion, Equipment Replacement - Estimated Cost: currency - Priority: choice with Low, Normal, High, Critical - Current Stage: choice with Draft, Technical Validation, Operations Review, Finance Review, Planning Approval, Implementation, Closed - Request Status: choice with Draft, Submitted, In Review, Approved, Rejected, Completed - SLA Status: choice with On Track, At Risk, Overdue - Business Justification: multiple lines of text
  1. Review the generated columns.
  2. Make small corrections if Copilot uses a different column type.
  3. Save the table.
Checkpoint: you should now have one table named Network Capacity Request with the columns above.

Lab 2: Create the model-driven app 15 min

  1. Create a model-driven app and name it Network Capacity Operations.
  2. Add the Network Capacity Request Dataverse table as a page.
  3. Name the navigation area Operations.
  4. Save and publish the app.
  5. Select Play and confirm that the three sample records appear.
  6. Open JKT-CBD-042 and review the generated form.
Checkpoint: you can navigate from the record list into an individual capacity request.

Lab 3: Customize the experience 15 min

A. Create three views

Create these simple system views. You do not need advanced filtering.

Active Requests

Show Site ID, Region, Peak Utilization, Priority, Current Stage and SLA Status.

At-Risk Requests

Filter SLA Status = At Risk or Overdue.

High Priority Requests

Filter Priority = High or Critical.

What this demonstrates

Different users can work from focused record lists instead of one large table.

B. Simplify the main form

  1. Edit the main form for Network Capacity Request.
  2. Keep the most important fields near the top: Site ID, Region, Peak Utilization, Priority, Current Stage, Request Status, and SLA Status.
  3. Add a section called Upgrade Details with Requested Upgrade, Estimated Cost, and Business Justification.
  4. Save and publish.
  5. Play the app again and open JKT-CBD-042.
Try it: change JKT-CBD-042 from Draft to Submitted and save it. This demonstrates that the model-driven app is operational, not only a dashboard.

Lab 4: Add a simple visual 10 min

  1. Open the Network Capacity Request table configuration.
  2. Create a chart named Requests by Stage.
  3. Use Current Stage as the category.
  4. Use the number of Network Capacity Request records as the value.
  5. Save and publish the chart.
  6. Return to the app and open the record list.
  7. Display the chart and compare the records across stages.
Final checkpoint: you now have a working operational app with data, views, a customized record page, and a chart.

Bonus if you finish early

Choose one extension only:

  • Create a view filtered to Region = Jakarta.
  • Add a new field called Current Approver.
  • Add another chart for Requests by SLA Status.
  • Change JKT-CBD-042 to Finance Review and observe how the chart changes.
Facilitator extension: multi-step approvals, Approval Step records, Power Automate routing, security roles, and SLA escalation are best shown by the facilitator after the one-hour participant build.

What you learned

  • How Dataverse provides the structured data foundation.
  • How a model-driven app quickly turns the table into a usable operational application.
  • How views help different users focus on relevant records.
  • How forms control what users see and modify on a record.
  • How charts create a simple monitoring experience over live Dataverse records.

Key takeaway: start with the data and process, then progressively customize the app experience where the business needs it.
